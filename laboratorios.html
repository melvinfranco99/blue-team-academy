Paso 1

Arquitectura del laboratorio

Requisitos

  • PC con 16 GB RAM (8 GB mínimo, encendiendo menos VMs), 150 GB libres.
  • Virtualización activada en la BIOS (VT-x / AMD-V).
  • Software: VirtualBox o VMware Workstation Pro (gratis para uso personal).

Alternativas “todo en uno”

  • Security Onion: Suricata + Zeek + Elastic ya integrados.
  • Wazuh: SIEM/XDR libre con agentes para Windows y Linux.
  • Plataformas online: TryHackMe (rutas SOC Level 1/2), Blue Team Labs Online, LetsDefend, HTB Sherlocks, CyberDefenders.
Paso 2

Montaje paso a paso

  1. Crear la red aislada

    En VirtualBox: Archivo → Herramientas → Network Manager → Host-only Networks → Crear con 192.168.56.1/24. Asigna esa red a todas las VMs. Para descargar paquetes, añade temporalmente un segundo adaptador NAT y quítalo después.

  2. VM del analista (Ubuntu o Kali)

    sudo apt update && sudo apt install -y nmap wireshark tcpdump jq python3-pip
sudo usermod -aG wireshark $USER   # capturar sin root

  3. SIEM: Splunk Free (o Wazuh)

    # Splunk (Ubuntu, 8 GB RAM recomendado)
sudo dpkg -i splunk-9.x-linux-amd64.deb
sudo /opt/splunk/bin/splunk start --accept-license
sudo /opt/splunk/bin/splunk enable listen 9997 -auth admin:TU_PASSWORD
# Alternativa Wazuh (all-in-one)
curl -sO https://packages.wazuh.com/4.x/wazuh-install.sh && sudo bash ./wazuh-install.sh -a

  4. Sensor: Suricata + Zabbix

    sudo add-apt-repository ppa:oisf/suricata-stable -y
sudo apt install -y suricata && sudo suricata-update
sudo nano /etc/suricata/suricata.yaml   # HOME_NET y interfaz
sudo systemctl restart suricata

    Para que el sensor vea el tráfico de las demás VMs, activa en su adaptador Modo promiscuo: Permitir todo.

  5. Víctimas

    web01 con Apache y Universal Forwarder; Windows 10/11 o Server de evaluación con Sysmon (configuración de SwiftOnSecurity u Olaf Hartong) y Universal Forwarder; y Metasploitable 2 solo en la red aislada.

    # Windows (PowerShell como administrador)
.\Sysmon64.exe -accepteula -i sysmonconfig-export.xml
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 5

  6. Haz un snapshot

    Guarda una instantánea de cada VM “limpia”. Así podrás romper cosas y volver atrás en segundos.

Paso 3

Ejercicios guiados

Cada ejercicio indica nivel, objetivo, video de apoyo y solución. Intenta resolverlo antes de abrir la solución.

E1 · Inventario de la red con Nmap

Objetivo: descubre todos los hosts vivos y sus servicios, guarda una línea base y detecta un cambio.

Pista: -sn, -sV, -oA, ndiff. Después arranca un servicio nuevo en web01 (python3 -m http.server 8888) y repite.

Ver solución
sudo nmap -sn 192.168.56.0/24
sudo nmap -sS -sV -oA base 192.168.56.0/24
# (en web01) python3 -m http.server 8888
sudo nmap -sS -sV -oA hoy 192.168.56.0/24
ndiff base.xml hoy.xml     # → +8888/tcp open http SimpleHTTPServer
▶ Video de apoyo: Nmap

E2 · Detecta un escaneo en una captura

Objetivo: captura tráfico mientras otra VM te escanea e identifica la IP atacante y cuántos puertos tocó.

Ver solución
sudo tcpdump -i eth0 -w scan.pcap        # en la víctima
sudo nmap -sS 192.168.56.20               # desde el analista
tcpdump -nr scan.pcap 'tcp[tcpflags]==tcp-syn' | awk '{print $3}' | cut -d. -f1-4 | sort | uniq -c
# Wireshark: tcp.flags.syn==1 && tcp.flags.ack==0  → Statistics → Conversations
▶ Video de apoyo: Redes

E3 · Lee logs de autenticación

Objetivo: genera 10 intentos SSH fallidos contra web01 y encuéntralos en /var/log/auth.log, contando por IP.

Ver solución
grep "Failed password" /var/log/auth.log | grep -oE 'from [0-9.]+' | sort | uniq -c | sort -rn
# o con journalctl:
journalctl -u ssh --since "1 hour ago" | grep Failed

E4 · Tu primera regla de Suricata

Objetivo: crea una regla que alerte cuando alguien haga una petición HTTP con User-Agent sqlmap y verifícala en eve.json.

Ver solución
# /etc/suricata/rules/local.rules
alert http any any -> $HOME_NET any (msg:"LAB sqlmap UA"; http.user_agent; content:"sqlmap"; nocase; sid:1100010; rev:1;)
sudo suricata -T -c /etc/suricata/suricata.yaml && sudo systemctl restart suricata
curl -A "sqlmap/1.8" http://192.168.56.20/
jq 'select(.event_type=="alert") | .alert.signature' /var/log/suricata/eve.json

E5 · Detección de fuerza bruta en Splunk

Objetivo: envía auth.log a Splunk y crea una alerta programada que dispare con >20 fallos en 5 min por IP. Bonus: indica si alguna IP tuvo éxito.

Ver solución
index=linux sourcetype=linux_secure ("Failed password" OR "Accepted password")
| rex "(?<res>Failed|Accepted) password for (invalid user )?(?<user>\S+) from (?<src_ip>\S+)"
| bin _time span=5m
| stats count(eval(res="Failed")) as fallos count(eval(res="Accepted")) as exitos dc(user) as usuarios by _time src_ip
| where fallos > 20
▶ Video: Splunk

E6 · Trigger de seguridad en Zabbix

Objetivo: alerta si cambia /etc/passwd en web01. Pruébalo creando un usuario.

Ver solución
Item:    vfs.file.cksum[/etc/passwd,sha256]   (cada 1m, tipo texto)
Trigger: change(/web01/vfs.file.cksum[/etc/passwd,sha256])<>0   Severidad: High
Prueba:  sudo useradd pruebaLab
▶ Video: Zabbix

E7 · Simula y detecta Office → PowerShell

Objetivo: con Sysmon en Windows, simula la técnica T1059.001 (por ejemplo con Atomic Red Team) y crea la detección en Splunk a partir de la regla Sigma del video.

Ver solución
# Windows (laboratorio): instalar Invoke-AtomicRedTeam y ejecutar un test de T1059.001
Invoke-AtomicTest T1059.001 -TestNumbers 1
# Splunk (Sysmon EventCode 1)
index=sysmon EventCode=1 (ParentImage="*\\WINWORD.EXE" OR ParentImage="*\\EXCEL.EXE")
  (Image="*\\powershell.exe" OR Image="*\\cmd.exe")
| table _time host User ParentImage Image CommandLine

E8 · Caza de beaconing

Objetivo: en una VM, ejecuta un “beacon” inofensivo (while true; do curl -s http://192.168.56.5:8000/ >/dev/null; sleep 30; done) y encuéntralo por su regularidad.

Ver solución
# Con eve.json de Suricata (event_type=http) o logs de proxy
jq -r 'select(.event_type=="http") | [.timestamp,.src_ip,.http.hostname] | @tsv' eve.json > http.tsv
# En Splunk: streamstats + stdev (ver lección 12) → desviación ≈ 0 s, media ≈ 30 s

E9 · Mini-incidente completo

Objetivo: un compañero (o tú con un script) crea un usuario con UID 0 en web01, lanza un proceso que consume CPU y abre un puerto nuevo. Detecta los tres hechos con Zabbix, Nmap/ndiff y Splunk, y redacta un informe siguiendo las fases NIST.

Plantilla de informe
1. Resumen ejecutivo (3 líneas)
2. Línea temporal (hora · fuente · evento)
3. Alcance (hosts, cuentas, datos)
4. Contención / erradicación / recuperación realizadas
5. Causa raíz
6. Lecciones aprendidas y acciones (responsable + fecha)
